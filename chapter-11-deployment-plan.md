## 4. Hosting Platform Assessment: Vercel

Vercel is the native cloud deployment platform for Next.js and provides optimal runtime characteristics for the KOD Technical Services web application:

### 4.1 Technical Architecture Compatibility
- **Next.js 15.5.28 & React 19 Support:** Full native support for App Router, server components, streaming SSR, and font/image optimization.
- **Static Site Generation (SSG):** All 18 public content routes are pre-rendered into static HTML at build time, ensuring sub-50ms TTFB across Vercel's global edge network (Anycast CDN).
- **Serverless API Route (`POST /api/rfq`):** Executes in an isolated Node.js serverless execution context with automatic regional routing, fast cold-starts, and TLS termination.
- **Zero In-Memory State Dependency:** The RFQ system has been decoupled from single-instance RAM via Upstash Redis REST integration, enabling horizontal scaling without state corruption.
- **SSL/TLS & HTTPS:** Automatic certificate issuance and maintenance via Let's Encrypt / DigiCert with HTTP to HTTPS 308 permanent redirects enforced at the edge.
- **Zero-Downtime Atomic Deployments:** Every commit or deployment generates an immutable preview build. Instant rollback to any previous deployment hash is available with zero downtime.

- **Vercel CLI Availability:** Vercel CLI version `51.4.0` is available locally in the node environment.
- **Authentication State:** No interactive or cached Vercel session credentials exist in the local workspace (`npx vercel whoami` requests interactive login).

- **Verdict:** Because external cloud credentials must never be fabricated, automated deployment will proceed once the user connects the project to Vercel via GitHub or authenticates the Vercel CLI.

## 6. Production Environment Variables Specification

The following environment variables govern application behavior across Preview and Production environments:

| Variable Name | Required In | Purpose | Default / Fallback | Recommended Value for Vercel |
| :--- | :---: | :--- | :--- | :--- |
| `NEXT_PUBLIC_SITE_URL` | Preview & Production | Sets canonical base URL for metadata, sitemaps, and robots | `https://kodtechnical.vercel.app` | `https://kodtechnical.vercel.app` |
| `SITE_URL` | Preview & Production | Server-side canonical base URL | `https://kodtechnical.vercel.app` | `https://kodtechnical.vercel.app` |
| `RESEND_API_KEY` | Production | API key for transactional email delivery via Resend | `None` (returns HTTP 503 unconfigured) | Real Resend API key (`re_...`) |
| `RFQ_SENDER_EMAIL` | Production | Verified sending address for quote notifications | `"KOD Engineering Desk <quotes@kodtechnical.com>"` | `"KOD Engineering Desk <quotes@kodtechnical.com>"` |
| `RFQ_RECIPIENT_EMAIL` | Production | Destination inbox for engineering RFQ alerts | `info@kodtechnical.com` | `info@kodtechnical.com` |
| `RFQ_MOCK_DELIVERY` | Preview / Staging | Bypasses live Resend dispatch; simulates success with reference ID | `false` in production | `true` for Staging/Preview; `false` for Production |
| `UPSTASH_REDIS_REST_URL` | Production | Distributed Redis endpoint for cluster-wide rate limiting & idempotency | `None` (falls back to in-memory sliding window) | `https://<db>.upstash.io` |
| `UPSTASH_REDIS_REST_TOKEN` | Production | REST token for Upstash Redis cluster | `None` | Upstash bearer token |

> [!IMPORTANT]
> In production, `RFQ_MOCK_DELIVERY` must be explicitly set to `false`. If `RESEND_API_KEY` is not supplied, the RFQ system will cleanly inform the customer that the email channel is undergoing maintenance and automatically provide one-click fallback options (direct email to `info@kodtechnical.com`, WhatsApp dispatch, and phone hotline).

## 9. Staging & Production Deployment Procedures

### Procedure A: Deployment via Vercel GitHub Integration (Recommended)
1. Initialize git commits on `master`:
   ```bash
   git add .
   git commit -m "feat(release): production-ready KOD Technical Services web application"
   ```
2. Push repository to GitHub:
   ```bash
   git remote add origin https://github.com/<org>/kod-technical-website.git
   git branch -M main
   git push -u origin main
   ```
3. In Vercel Dashboard ([vercel.com/new](https://vercel.com/new)):
   - Select the GitHub repository.
   - Framework Preset: **Next.js**.
   - Root Directory: `./`.
   - Configure Environment Variables (from Section 6).
   - Click **Deploy**.
4. In Project Settings > Domains:
   - Verify assigned domain is `kodtechnical.vercel.app`.

### Procedure B: Direct Deployment via Vercel CLI
1. Log in to Vercel:
   ```bash
   npx vercel login
   ```
2. Link and deploy staging preview:
   ```bash
   npx vercel
   ```
3. Deploy to production:
   ```bash
   npx vercel --prod
   ```
4. Assign production alias:
   ```bash
   npx vercel alias set <deployment-url> kodtechnical.vercel.app
   ```

## 10. Rollback & Contingency Plan

1. **Instant Rollback via Vercel Dashboard:**
   - Navigate to **Deployments** in the Vercel dashboard.
   - Locate the previous stable deployment hash.
   - Click the three dots (`...`) and select **Instant Rollback**.
   - Vercel instantly routes 100% of traffic to the chosen build within seconds with zero downtime.
2. **Emergency RFQ Deactivation:**
   - If Resend or email deliverability experiences upstream failures, set `RFQ_MOCK_DELIVERY=true` in Vercel project environment variables and trigger redeployment, or unset `RESEND_API_KEY` to let the system activate transparent client-side fallbacks.
3. **Preservation of Legacy Assets:**
   - The original WordPress installation backup and assets remain safely preserved in `public/images/` and historical documentation.
